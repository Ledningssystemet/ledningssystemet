# Production Installation on Ubuntu Server

This guide describes a complete installation of Ledningssystemet with:

- Ubuntu Server 26.04 LTS or 24.04 LTS
- MariaDB on the server
- Ledningssystemet as a Docker container from GitHub Container Registry
- Nginx as a reverse proxy
- HTTPS certificates from Let's Encrypt
- persistent storage and a mounted `.env` file
- automatic database backups and container updates
- basic Linux, SSH, MariaDB, Docker, and Nginx hardening

The commands assume a fresh 64-bit Ubuntu Server installation and a user account with
`sudo` privileges. Replace the following example values before installation:

- `ledning.example.se`: the server's public DNS name
- `admin@example.se`: address for Let's Encrypt notifications
- `deploy`: your administrative Linux account

> [!IMPORTANT]
> The DNS A record and any AAAA record must point to the server. TCP ports 80 and
> 443 must be reachable from the internet. Never publish port 3306 or
> the application's internal port 8000.

## 2. Basic Installation and Linux Hardening

### 2.1 Update the server

```bash
sudo apt update
sudo apt full-upgrade -y
sudo apt install -y \
  ca-certificates curl gnupg openssl ufw fail2ban unattended-upgrades \
  apt-listchanges auditd apparmor apparmor-utils jq
sudo systemctl enable --now auditd apparmor fail2ban
sudo reboot
```

Log in again after the reboot.

### 2.2 Administrative account and SSH key

If the installation account is not already the account to be used:

```bash
sudo adduser deploy
sudo usermod -aG sudo deploy
sudo install -d -m 0700 -o deploy -g deploy /home/deploy/.ssh
sudoedit /home/deploy/.ssh/authorized_keys
sudo chown deploy:deploy /home/deploy/.ssh/authorized_keys
sudo chmod 0600 /home/deploy/.ssh/authorized_keys
```

Paste the public SSH key into `authorized_keys`. Verify in a **new
terminal** that key-based login works before disabling password authentication.

Then create a separate SSH configuration:

```bash
sudo tee /etc/ssh/sshd_config.d/60-hardening.conf >/dev/null <<'EOF'
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
PubkeyAuthentication yes
PermitEmptyPasswords no
X11Forwarding no
AllowTcpForwarding no
AllowAgentForwarding no
MaxAuthTries 3
LoginGraceTime 30
ClientAliveInterval 300
ClientAliveCountMax 2
AllowUsers deploy
EOF

sudo sshd -t
sudo systemctl reload ssh
```

If the account is not named `deploy`, `AllowUsers` must be changed before SSH is reloaded.
If SSH tunnels are needed in operations, `AllowTcpForwarding` can be set to `local`.

### 2.3 Firewall

Allow SSH before enabling the firewall:

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw limit OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw deny 3306/tcp
sudo ufw logging medium
sudo ufw enable
sudo ufw status verbose
```

If SSH uses a port other than 22, allow the corresponding port before
`ufw enable`.

Docker-published ports can bypass UFW. The Compose configuration in this
guide therefore explicitly binds the application port to `127.0.0.1`. Do not
change this to `0.0.0.0`.

## 3. Install and Harden MariaDB

### 3.1 Installation

Install the Ubuntu version's security-maintained MariaDB:

```bash
sudo apt install -y mariadb-server mariadb-client
sudo systemctl enable --now mariadb
sudo mariadb-secure-installation
```

- remove the test database
- reload the privilege tables

### 3.2 Create TLS Certificates for MariaDB

The application and the database communicate over a local Docker network, but TLS
is still used to protect credentials and verify the server.

```bash
sudo install -d -m 0750 -o root -g mysql /etc/mysql/tls
cd /tmp

sudo openssl genrsa -out /etc/mysql/tls/ca.key 4096
sudo openssl req -x509 -new -nodes \
  -key /etc/mysql/tls/ca.key \
  -sha256 -days 3650 \
  -subj "/CN=Ledningssystemet MariaDB CA" \
  -out /etc/mysql/tls/ca.crt

sudo openssl genrsa -out /etc/mysql/tls/server.key 3072

cat <<'EOF' | sudo tee /etc/mysql/tls/server.cnf >/dev/null
[req]
prompt = no
distinguished_name = dn
req_extensions = v3_req

[dn]
CN = 172.30.0.1

[v3_req]
subjectAltName = IP:172.30.0.1,DNS:host.docker.internal
extendedKeyUsage = serverAuth
keyUsage = critical,digitalSignature,keyEncipherment
EOF

sudo openssl req -new \
  -key /etc/mysql/tls/server.key \
  -config /etc/mysql/tls/server.cnf \
  -out /etc/mysql/tls/server.csr

sudo openssl x509 -req \
  -in /etc/mysql/tls/server.csr \
  -CA /etc/mysql/tls/ca.crt \
  -CAkey /etc/mysql/tls/ca.key \
  -CAcreateserial \
  -out /etc/mysql/tls/server.crt \
  -days 825 -sha256 \
  -extensions v3_req \
  -extfile /etc/mysql/tls/server.cnf

sudo chown root:root /etc/mysql/tls/ca.crt
sudo chown mysql:mysql /etc/mysql/tls/server.key /etc/mysql/tls/server.crt
sudo chmod 0644 /etc/mysql/tls/ca.crt
sudo chmod 0640 /etc/mysql/tls/server.crt
sudo chmod 0600 /etc/mysql/tls/ca.key /etc/mysql/tls/server.key
sudo rm /etc/mysql/tls/server.csr
```

The CA key `/etc/mysql/tls/ca.key` must be backed up encrypted and never
mounted into the container. The server certificate is valid for 825 days and must be renewed
before then.

### 5.4 Create the docker-compose.yaml

The following command uses the `APP_KEY` and `DB_PASSWORD` values from the same
terminal session as the previous steps:

```bash
name: ledningssystemet

services:
  app:
    image: ghcr.io/ledningssystemet/ledningssystemet:latest
    pull_policy: missing
    restart: unless-stopped
    ports:
      - "127.0.0.1:8000:80"
    volumes:
      - type: bind
        source: /opt/ledningssystemet/.env
        target: /var/www/html/.env
        read_only: true
      - type: bind
        source: /opt/ledningssystemet/storage
        target: /var/www/html/storage
      - type: bind
        source: /etc/mysql/tls/ca.crt
        target: /var/www/html/sql-ca.pem
        read_only: true
    networks:
      app:
        ipv4_address: 172.30.0.2
    pids_limit: 512
    mem_limit: 2g
    cpus: 2.0
    security_opt:
      - no-new-privileges:true
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "5"

networks:
  app:
    name: ledningssystemet
    driver: bridge
    driver_opts:
      com.docker.network.bridge.name: br-ledning
      com.docker.network.bridge.enable_icc: "false"
    ipam:
      config:
        - subnet: 172.30.0.0/24
          gateway: 172.30.0.1
EOF

sudo chown root:root /opt/ledningssystemet/compose.yaml
sudo chmod 0644 /opt/ledningssystemet/compose.yaml
cd /opt/ledningssystemet
sudo docker compose config --quiet
sudo docker compose create
```

Adjust resource limits according to server capacity and load. Do not set a
memory limit lower than the PHP processes' actual peak requirement.

The Compose network is now created with the predictable interface `br-ledning`.
Only allow TLS connections from this network to MariaDB:

```bash
sudo ufw insert 1 allow in on br-ledning from 172.30.0.0/24 \
  to 172.30.0.1 port 3306 proto tcp \
  comment 'Ledningssystemet to MariaDB'
sudo ufw status numbered
```

### 6.3 Hardened HTTPS Configuration

Create a reusable proxy configuration:

```bash
sudo tee /etc/nginx/snippets/ledningssystemet-proxy.conf >/dev/null <<'EOF'
proxy_http_version 1.1;
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $remote_addr;
proxy_set_header X-Forwarded-Host $host;
proxy_set_header X-Forwarded-Port 443;
proxy_set_header X-Forwarded-Proto https;
proxy_set_header Connection "";
proxy_hide_header X-Powered-By;
proxy_connect_timeout 10s;
proxy_send_timeout 120s;
proxy_read_timeout 120s;
proxy_request_buffering on;
proxy_buffering on;
proxy_pass [http://127.0.0.1:8000](http://127.0.0.1:8000);
EOF
```

Replace the site configuration:

```bash
sudo tee /etc/nginx/sites-available/ledningssystemet >/dev/null <<'EOF'
limit_req_zone $binary_remote_addr zone=login:10m rate=10r/m;

server {
    listen 80;
    listen [::]:80;
    server_name ledning.example.se;

    location ^~ /.well-known/acme-challenge/ {
        root /var/www/letsencrypt;
        default_type text/plain;
        try_files $uri =404;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;
    server_name ledning.example.se;

    ssl_certificate /etc/letsencrypt/live/ledning.example.se/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ledning.example.se/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:SSL:20m;
    ssl_session_timeout 1d;
    ssl_session_tickets off;

    server_tokens off;
    client_max_body_size 128m;

    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Permissions-Policy "camera=(), geolocation=(), microphone=()" always;

    access_log /var/log/nginx/ledningssystemet-access.log;
    error_log /var/log/nginx/ledningssystemet-error.log warn;

    location = /login {
        limit_req zone=login burst=10 nodelay;
        include /etc/nginx/snippets/ledningssystemet-proxy.conf;
    }

    location / {
        include /etc/nginx/snippets/ledningssystemet-proxy.conf;
    }

    location ~ /\.(?!well-known) {
        deny all;
    }
}
EOF

sudo nginx -t
sudo systemctl reload nginx
```

Direct client values in `X-Forwarded-For` are overwritten at the edge proxy to
prevent IP spoofing. The application port is also only bound to
loopback, so Nginx is the only trusted path in.

Do not enable `includeSubDomains` or `preload` in HSTS until all
subdomains are permanently HTTPS-ready. A strict Content Security Policy should
be added after inventorying the application's actual script, style, and
integration sources; an incorrect policy can render the interface
unusable.

Verify the installation:

```bash
curl --head [https://ledning.example.se/login](https://ledning.example.se/login)
sudo ss -lntup
```

Only SSH as well as Nginx on 80/443 should be publicly listening. Port 8000 should show
as `127.0.0.1:8000`, and MariaDB should be blocked externally by UFW.

## 7. Backups

A functional backup must contain:

- MariaDB database
- `/opt/ledningssystemet/storage`
- `/opt/ledningssystemet/.env`
- MariaDB CA key and certificate, encrypted and protected separately
- Nginx and Compose configuration

The following local backup is a first line of protection, not a complete
disaster recovery solution. Synchronize `/var/backups/ledningssystemet` encrypted to another
server or object storage and test restores regularly.

```bash
sudo install -d -m 0700 -o root -g root /var/backups/ledningssystemet

sudo tee /usr/local/sbin/backup-ledningssystemet >/dev/null <<'EOF'
#!/usr/bin/env bash
set -Eeuo pipefail
umask 077

BACKUP_ROOT=/var/backups/ledningssystemet
STAMP="$(date -u +%Y%m%dT%H%M%SZ)"
TARGET="${BACKUP_ROOT}/${STAMP}"

mkdir -p "$TARGET"

mariadb-dump \
  --single-transaction \
  --routines \
  --triggers \
  --events \
  --hex-blob \
  --databases ledningssystemet |
  gzip -9 >"${TARGET}/database.sql.gz"

tar --xattrs --acls -C /opt/ledningssystemet \
  -czf "${TARGET}/storage.tar.gz" storage

install -m 0600 /opt/ledningssystemet/.env "${TARGET}/app.env"
install -m 0600 /opt/ledningssystemet/compose.yaml "${TARGET}/compose.yaml"

find "$BACKUP_ROOT" -mindepth 1 -maxdepth 1 -type d -mtime +30 -exec rm -rf -- {} +
EOF

sudo chmod 0750 /usr/local/sbin/backup-ledningssystemet
sudo /usr/local/sbin/backup-ledningssystemet
sudo find /var/backups/ledningssystemet -maxdepth 2 -type f -ls
```

Create a systemd service and timer:

```bash
sudo tee /etc/systemd/system/ledningssystemet-backup.service >/dev/null <<'EOF'
[Unit]
Description=Backup of Ledningssystemet
After=mariadb.service
Requires=mariadb.service

[Service]
Type=oneshot
ExecStart=/usr/local/sbin/backup-ledningssystemet
PrivateTmp=true
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/backups/ledningssystemet
ReadOnlyPaths=/opt/ledningssystemet
EOF

sudo tee /etc/systemd/system/ledningssystemet-backup.timer >/dev/null <<'EOF'
[Unit]
Description=Nightly backup of Ledningssystemet

[Timer]
OnCalendar=*-*-* 02:15:00
RandomizedDelaySec=15m
Persistent=true

[Install]
WantedBy=timers.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now ledningssystemet-backup.timer
sudo systemctl list-timers ledningssystemet-backup.timer
```

### 7.1 Restoration Example

```bash

```

Restore in an isolated test environment first. A restoration overwrites current
data and should never be done untested in production.

## 8. Automatic application updates

Automatic updates always carry risk because a new image may
contain database changes. The script below:

1. creates a backup
2. saves the current image locally as `rollback`
3. runs `docker compose pull`
4. starts the new image and waits for the health check
5. restores the previous image if the container does not become healthy

Database migrations can be irreversible. A container rollback therefore
does not replace the database backup. For business-critical operations, the same flow should first be run
in staging, and a tested SHA tag promoted to production.

```bash
sudo tee /usr/local/sbin/update-ledningssystemet >/dev/null <<'EOF'
#!/usr/bin/env bash
set -Eeuo pipefail

exec 9>/run/lock/update-ledningssystemet.lock
flock -n 9 || {
  echo "An update is already running." >&2
  exit 0
}

readonly APP_DIR=/opt/ledningssystemet
readonly IMAGE=ghcr.io/ledningssystemet/ledningssystemet:latest
readonly ROLLBACK_IMAGE=ghcr.io/ledningssystemet/ledningssystemet:rollback

cd "$APP_DIR"
/usr/local/sbin/backup-ledningssystemet

old_image="$(docker image inspect "$IMAGE" --format '{{.Id}}' 2>/dev/null || true)"
if [[ -n "$old_image" ]]; then
  docker image tag "$old_image" "$ROLLBACK_IMAGE"
fi

docker compose pull

if docker compose up -d --remove-orphans --wait --wait-timeout 180; then
  docker image prune -f
  echo "Ledningssystemet was updated: $(date --iso-8601=seconds)"
  exit 0
fi

echo "The new container did not become healthy. Restoring previous image." >&2
docker compose logs --tail=200 app >&2 || true

if docker image inspect "$ROLLBACK_IMAGE" >/dev/null 2>&1; then
  docker image tag "$ROLLBACK_IMAGE" "$IMAGE"
  docker compose up -d --force-recreate --remove-orphans \
    --pull never --wait --wait-timeout 180
else
  echo "No rollback image found. Manual intervention required." >&2
fi

exit 1
EOF

sudo chmod 0750 /usr/local/sbin/update-ledningssystemet
```

Test the script manually:

```bash
sudo /usr/local/sbin/update-ledningssystemet
cd /opt/ledningssystemet
sudo docker compose ps
```

Then create the timer and service:

```bash
sudo tee /etc/systemd/system/ledningssystemet-update.service >/dev/null <<'EOF'
[Unit]
Description=Pull and deploy the latest Ledningssystemet image
After=docker.service mariadb.service network-online.target
Requires=docker.service mariadb.service
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/local/sbin/update-ledningssystemet
Nice=10
IOSchedulingClass=best-effort
IOSchedulingPriority=7
EOF

sudo tee /etc/systemd/system/ledningssystemet-update.timer >/dev/null <<'EOF'
[Unit]
Description=Regular update of Ledningssystemet

[Timer]
OnCalendar=Mon..Fri *-*-* 04:15:00
RandomizedDelaySec=30m
Persistent=true

[Install]
WantedBy=timers.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now ledningssystemet-update.timer
sudo systemctl list-timers ledningssystemet-update.timer
```

View the latest run:

```bash
sudo systemctl status ledningssystemet-update.service
sudo journalctl -u ledningssystemet-update.service --since yesterday
```

For strict change control, omit the timer. Run the update script
manually after reviewing the version changes.

## 11. Troubleshooting

### The Container Cannot Reach MariaDB

```bash
ip address show br-ledning
sudo ufw status numbered
sudo ss -lntp | grep 3306
sudo journalctl -u mariadb --since "30 minutes ago"
sudo docker compose -f /opt/ledningssystemet/compose.yaml logs --tail=200 app
```

Verify that the network gateway is `172.30.0.1`, that MariaDB is listening, and that
the UFW rule for `br-ledning` exists.

### TLS verification against MariaDB fails

```bash
sudo openssl verify \
  -CAfile /etc/mysql/tls/ca.crt \
  /etc/mysql/tls/server.crt
sudo openssl x509 -in /etc/mysql/tls/server.crt -noout -text | \
  grep -A2 "Subject Alternative Name"
```

The certificate must verify and contain `IP Address:172.30.0.1`.
Do not disable certificate verification as a permanent solution.

### Incorrect HTTP Links or Redirect Loops

Check that:

- `APP_URL` starts with `https://`
- `SESSION_SECURE_COOKIE=true`
- Nginx sends `X-Forwarded-Proto https`
- Port 8000 is only reached via the local Nginx proxy

After modifying `.env`, the container must be recreated because the image caches
the Laravel configuration at startup:

```bash
cd /opt/ledningssystemet
sudo docker compose up -d --force-recreate --wait --wait-timeout 180
```

### Permission Errors in `storage`

```bash
sudo chown -R 33:33 /opt/ledningssystemet/storage
sudo find /opt/ledningssystemet/storage -type d -exec chmod 0750 {} +
sudo find /opt/ledningssystemet/storage -type f -exec chmod 0640 {} +
cd /opt/ledningssystemet
sudo docker compose restart app
```

Do not use `chmod -R 777`; it masks the root cause and makes data writable by
all local users.
